<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Authenticated campaign request → host composer | Request identity and active workspace determine which sender rows become presentation data. |
| Sender database values → Blade HTML | User-controlled label, From Name, and From Email cross into option text and data attributes. |
| Browser picker → package campaign request | Client-side convenience values enter the existing editable From fields; server validation remains authoritative. |
| Host override → SendPortal Core package | Published host views replace package views while the installed vendor tree remains immutable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-01 | Elevation of privilege | AppServiceProvider sender composer | high | mitigate | Resolve only through `auth()->user()->currentWorkspace()->senders()` and cover a second workspace in the focused render test. |
| T-06-02 | Information disclosure | Campaign picker options | high | mitigate | Keep the composer targeted to create/edit and assert foreign sender labels/emails are absent. |
| T-06-03 | Tampering / XSS | Published campaign partial | high | mitigate | Escape option text and data attributes with Blade interpolation; never concatenate sender values into executable JavaScript. |
| T-06-04 | Tampering | Convenience picker submission | medium | mitigate | Omit the select name, retain existing package request fields, and assert absence of `sender_id`/picker submission contract. |
| T-06-05 | Availability | Package view override drift | medium | mitigate | Synchronize the three copied views with v3.0.2, run rendered smoke checks, and document upgrade re-diff responsibility. |
| T-06-SC | Tampering | Package installs or vendor mutation | high | mitigate | Install no dependency, preserve the lock/security policy, and gate every task on an empty vendor diff. |
</threat_model>
