# Interface notes for the executor
# - Redis::throttle($key) returns Illuminate\Redis\Limiters\DurationLimiterBuilder.
#   Chain: ->allow(int $rate)->every(1)->block(int $seconds)->sleep(int $ms)->then(callable $ok, ?callable $onFail).
#   then() runs $ok inside the acquired 1-second window; on block timeout it calls $onFail
#   if given, else throws Illuminate\Contracts\Redis\LimiterTimeoutException.
# - SesMailAdapter exposes protected helpers to REUSE (never call parent::send()):
#   resolveClient(): SesClient, resolveMessageId(Result): string, getSendQuota(): array, $this->config (array).
# - Aws\Ses\Exception\SesException::getAwsErrorCode() reads $context['code']; construct in
#   tests as new SesException($message, $commandMock, ['code' => 'Throttling', 'message' => $awsMessage]).
# - Aws\Result is array-constructible: new Aws\Result(['MessageId' => 'id']) / new Aws\Result(['MaxSendRate' => 14.0]).
# - MailAdapterFactory::$adapterMap is public static; EmailServiceType::SES === 1.
# - Test env (phpunit.xml.dist): CACHE_DRIVER=array (Cache::lock/remember work in-process),
#   QUEUE_DRIVER=sync. The Redis limiter tests use the 'default' Redis connection and must
#   skip cleanly when Redis is unreachable (documented residual risk).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Horizon worker -> Amazon SES API | Untrusted throttle/quota responses (SesException) cross here; misclassification causes retry amplification or dropped sends. |
| Worker <-> shared Redis (default connection) | The DurationLimiter key coordinates <=20 worker processes; a wrong/store fallback silently breaks the global rate guarantee. |
| Worker -> getSendQuota() (SES) | Rate source; a stampede of GetSendQuota calls can itself be throttled by AWS. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of Service | DurationLimiter store fallback | high | mitigate | Assert the limiter resolves to a Redis connection and prove cross-process pacing with a >=2-context shared-key test (Task 5); prevents the silent per-process 20x overshoot. |
| T-04-02 | Denial of Service | Retry amplification (vendor 10x-loop x Horizon tries) | high | mitigate | Bounded in-send loop (max_send_attempts=3), Horizon tries=3 sole outer retry owner, named exhaustion exception (Task 4). |
| T-04-03 | Denial of Service | GetSendQuota cache stampede at ~5-min expiry | medium | mitigate | Cache::remember(300) + Cache::lock single-flight + last-known-good fallback (Task 2). |
| T-04-04 | Tampering / Repudiation | Daily-quota misclassified as retryable rate error | high | mitigate | Code-gated (Throttling) + message sub-branch fails fast on daily-quota (Task 3). |
| T-04-05 | Elevation (integrity) | Double-send from a new post-send wait window | medium | mitigate | All waiting strictly before sendEmail; return immediately on success; bounded block < 60s worker timeout; fault-injection test (Task 6). |
| T-04-06 | Information Disclosure | Excess log noise leaking send internals | low | accept | Capped at one info log line per LOCKED scope fence; no credentials logged. |
| T-04-07 | Tampering | Supply-chain via new dependency | low | accept | No composer require in this phase (LOCKED); Task 6/7 assert composer.* unchanged — no package-legitimacy checkpoint needed. |
