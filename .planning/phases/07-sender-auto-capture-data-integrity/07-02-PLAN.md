<assumptions>
- A1: The captured label convention is `trim(campaign.name)`, bounded with `Illuminate\Support\Str::substr` to 255 UTF-8 code points, with the exact fallback `Campaign sender` when the trimmed name is empty. This is the resolved plan assumption for the research label gap.
- A2: Blank, null, or whitespace-only normalized `from_name` or `from_email` is an intentional silent no-op: no partial sender row, warning, or failure log. A missing trusted `workspace_id` is a capture failure.
- A3: Equality means exact equality after `Sender::normalizeInput`; no byte-level, grapheme-level, IDN, or additional case-folding predicate is introduced. SENDER-07 empty, single-element, and null inputs therefore resolve to no-op or one normalized row, never a collection merge.
- A4: SENDER-09 adjacency is not meaningful for independent sender, campaign, or message rows: equal or touching values neither merge nor collide beyond the existing unique normalized pair, and no list-order guarantee is part of the contract.
- A5: Web failures use the fixed session warning from 07-01. API failures use the additive `X-SendPortal-Warning` response header with the fixed value `The campaign was saved, but its sender could not be saved automatically.`; the package JSON body and status remain unchanged. No raw exception, sender value, or user-controlled campaign text is returned or logged.
</assumptions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| API client -> package campaign route -> host middleware | An untrusted API caller receives a response after a package-owned campaign write; the warning transport must not reflect request or exception content. |
| Authenticated/API-token workspace -> campaign observer -> sender insert | `Campaign::workspace_id` is trusted only after the existing workspace route/token boundary; it selects the tenant for the derived sender row. |
| Sender CRUD -> stored campaign/message snapshots | Mutable sender-library data must not cross into already persisted campaign or message From fields. |
| Application logs -> operators/log aggregation | Exception diagnostics cross into an operational sink and must not contain raw sender values, campaign text, or secrets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-07-02-01 | Tampering | `AttachSenderCaptureWarningHeader` | high | mitigate | Use a fixed request attribute and fixed `X-SendPortal-Warning` value; never interpolate request, campaign, sender, or exception text. |
| T-07-02-02 | Information disclosure | `CampaignObserver` logging and web/API warning paths | high | mitigate | Log only fixed event text, trusted numeric IDs, exception class, and numeric code; expose only the bounded user-facing warning. |
| T-07-02-03 | Elevation of privilege | workspace-scoped integrity tests and sender mutation path | high | mitigate | Preserve `RequireWorkspace`, existing API-token workspace resolution, trusted campaign `workspace_id`, and the `(workspace_id, from_name, from_email)` unique index; never query a global sender pair. |
| T-07-02-04 | Tampering | campaign/message historical snapshots | high | mitigate | Keep campaign and message From columns independent, avoid sender relations and foreign keys, and verify edit/delete/recreate behavior across all four message states. |
| T-07-02-05 | Repudiation | capture-failure recovery | medium | mitigate | Record a structured warning with safe campaign/workspace identifiers while keeping the original campaign transaction successful and test the exact recovery boundary. |
| T-07-02-SC | Supply-chain | Composer/npm/pip/cargo installs | low | accept | This plan installs no package and performs no external API or SDK integration; `07-COVERAGE.md` records the opt-out. |
