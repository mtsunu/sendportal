<assumptions>
- A1: The auto-captured label is the campaign name after trimming, bounded to 255 UTF-8 code points with Illuminate\Support\Str::substr, and uses the exact fallback `Campaign sender` when the trimmed name is empty. No provenance field is added.
- A2: Sender identity input is normalized only through App\Models\Sender::normalizeInput: trim all three fields and lowercase From Email. Pair equality is exact equality of those normalized strings; no grapheme, byte-level custom comparison, IDN conversion, or additional case folding is introduced.
- A3: Empty, null, or whitespace-only From Name or From Email is an intentional no-op because there is no complete sender identity to store. It creates no partial row and does not warn; a single valid campaign creates at most one sender.
- A4: Sender rows do not merge, collide, or order with campaign/message rows. SENDER-09 compares exact copied values on each independent row; equal values retain their own row values and no collection-order guarantee is required.
- A5: Plan 01 implements the web session warning and safe log recovery. Plan 02 adds the equivalent API response header while preserving the package JSON body.
</assumptions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| package web/API request to vendor Campaign repository | Untrusted request fields enter package validation; the repository assigns the trusted workspace_id before Campaign::save(). |
| persisted Campaign to host capture service | Campaign fields are treated as data; workspace_id is the tenant authority and is never taken from a sender/request field. |
| capture service to senders database | Derived label and normalized identity values cross into a parameterized insert and the existing workspace unique index. |
| observer recovery to logs/session | Failure visibility crosses into logs and user-facing warning state; content must remain fixed/bounded. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-07-01 | Tampering/Elevation | CampaignObserver workspace selection | high | mitigate | Use only the persisted Campaign workspace_id assigned by BaseTenantRepository; never read request workspace_id or current auth workspace inside capture. |
| T-07-02 | Tampering/Denial | CaptureCampaignSender duplicate insert | high | mitigate | Use the existing composite workspace/name/email unique index with parameterized insertOrIgnore and no label-updating conflict path; verify zero-row outcomes. |
| T-07-03 | Tampering/Denial | Campaign-derived sender label and input bounds | medium | mitigate | Reuse Sender::normalizeInput, bound the derived label to 255 UTF-8 code points, and let the query builder bind all values. |
| T-07-04 | Information Disclosure | CampaignObserver logging and web warning | medium | mitigate | Log only fixed event text, IDs, exception class/code, and show a fixed warning without raw sender values or exception messages. |
| T-07-SC | Tampering | Composer/package installs | low | accept | No package-manager install or dependency task exists; the plan verifies composer manifests and vendor/mettle/sendportal-core remain untouched. |
</threat_model>
